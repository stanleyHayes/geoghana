# GhanaGeo V2.0 Distribution — Business Requirements

**Status:** Draft for approval  
**Scope:** EP-23 SDK Family Expansion  
**Decision owner:** Product and Engineering Lead

## Purpose

Make GhanaGeo dependable from the languages Ghanaian public-service,
logistics, research and mobile teams already use. V2.0 must expand reach
without creating seven subtly different APIs. TypeScript is the reference
implementation; Python, Go, Dart, Java, C# and PHP must conform to the same
published behavior.

## Outcomes

1. TypeScript, Python, Go, Dart, Java, C# and PHP clients pass one
   language-neutral conformance suite.
2. Every SDK exposes the same operations, errors, pagination behavior, API
   version and tested dataset version while remaining idiomatic in its language.
3. A contract change cannot merge if it breaks a supported SDK.
4. Every published quick start is compiled and tested from source.
5. No SDK embeds a default credential, records sensitive request data, or
   retries unsafe operations implicitly.

## Users

- Web and Node developers using TypeScript.
- Data/research teams using Python and GeoPandas.
- Backend and cloud teams using Go, Java, C# or PHP.
- Flutter teams using Dart and region-scoped offline data.
- Maintainers responsible for contract compatibility and coordinated releases.

## In scope

- TypeScript reference-SDK completion and conformance.
- Six additional language SDKs named in EP-23.
- REST client parity for all public V1 operations; generated protobuf types and
  documented gRPC integration where the language ecosystem supports it.
- Shared conformance fixtures/runners, SDK charter, release automation and
  tested documentation snippets.
- Independent code SemVer and explicit tested dataset version.

## Out of scope

- New API endpoints or contract changes made only to simplify an SDK.
- Enterprise authentication, private datasets, billing or paid capabilities.
- GhanaPostGPS integration.
- Turn-by-turn navigation, worldwide geocoding or V2.2 data-depth work.
- Publishing before the V1 public-launch and contract-freeze gates pass.

## Success measures

- 100% of required conformance cases pass in all seven languages.
- Zero undocumented differences in error, pagination or cancellation behavior.
- Every release artifact installs in a clean consumer project and contains no
  credential-shaped values.
- Contract pull requests report every affected SDK before merge.
- Quick-start CI has zero stale or hand-written snippets.

## Entry and exit gates

Discovery and planning may proceed now. Implementation begins only after:

- V1 is publicly deployed;
- REST, GraphQL and gRPC contracts have remained frozen for one release cycle;
- this BRD, the PRD and architecture plan are approved;
- registry/repository ownership and release credentials are assigned.

V2.0 exits when every language is published, documented, conformance-green and
verified from a clean consumer environment.

## Decisions requested

1. Approve TypeScript as the normative behavioral reference while keeping the
   contracts—not TypeScript syntax—the ultimate source of truth.
2. Approve dedicated repositories for the six new language SDKs, with contracts,
   conformance fixtures and TypeScript retained in this canonical monorepo.
3. Approve independent SemVer per SDK with a coordinated compatibility matrix,
   rather than forcing every language to share one version number.
