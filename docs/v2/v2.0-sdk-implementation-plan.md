# GhanaGeo V2.0 SDK Implementation Plan

**Status:** Approved for implementation on 2026-08-29
**Execution rule:** Complete dependency-bound phases consecutively. The client
approved the BRD, PRD, architecture and this plan. V1 public launch, the
one-release-cycle contract freeze, registry ownership and publishing
credentials remain external release gates: they block public release, not
local implementation, conformance, artifact rehearsal or documentation work.
Record those gates explicitly and continue with the next unblocked story.

## Phase 0 — Documentation and contract baseline

### Work

- Record immutable V1 OpenAPI/protobuf/GraphQL/error-catalog checksums.
- Inventory the public operation/error/quota surface.
- Resolve TypeScript compiler support and the stale Next.js example as explicit
  baseline issues.
- Confirm registry namespaces, repository ownership and trusted publishing for
  all seven languages.

### References

- `contracts/openapi/v1.yaml`
- `proto/ghanageo/v1/geography.proto`
- `contracts/graphql/schema.graphql`
- `contracts/errors/catalog.yaml`
- `packages/client/src/index.ts`
- `packages/client/tests/client.test.ts`
- `packages/react/examples/next16/`
- `docs/runbooks/sdk-release.md`

### Allowed contract tooling

- Use the repository's pinned `openapi-typescript` command in
  `packages/core/package.json` for TypeScript OpenAPI models; do not invent a
  second TypeScript generator during baseline work.
- Use `buf lint`, `buf breaking --against <baseline>` and `buf generate` as
  configured by `buf.yaml` and `buf.gen.yaml`. Buf's `FILE` compatibility tier
  remains mandatory for a multi-language generated surface.
- Use `services/api/cmd/gencontracts` for error artifacts; do not hand-edit its
  generated Go or TypeScript outputs.
- Treat the published OpenAPI 3.1 contract as authoritative. Schema validation
  assists review but does not replace semantic conformance cases.

Official references: [OpenAPI Specification](https://spec.openapis.org/oas/),
[Buf breaking-change detection](https://buf.build/docs/breaking/), and
[Buf code generation](https://buf.build/docs/generate/).

### Verification

- Contract checksums and public-operation inventory are reviewed.
- Every registry/repository has a named owner.
- V1 public-launch and one-release-cycle freeze evidence is linked.

### Guards

- Do not infer behavior from generated code when the contract is explicit.
- Do not begin SDK coding during discovery.

## Phase 1 — GEO-24.1 conformance foundation

### Work

- Add schema-validated YAML cases and normalized report schema under
  `contracts/conformance/`.
- Build deterministic fixture/test-server orchestration.
- Copy semantic cases from REST/gRPC contract tests and existing TypeScript
  acceptance tests; preserve their expected public names and error codes.
- Add the TypeScript runner first, then a runner contract/test kit for other SDKs.

`GEO-24.1` is the bootstrap gate. Each later SDK adds its runner to the same
matrix; `GEO-24.1M` closes the complete matrix after all language stories and
before coordinated release. This avoids making the foundation both block and
require every downstream SDK.

### Verification

- Schema validation rejects malformed and secret-shaped fixtures.
- Every public operation and Appendix B error maps to at least one required case.
- Repeated local runs produce byte-equivalent normalized reports.
- CI fails when a runner skips a required case.

### Guards

- Generated cases never replace curated semantic cases.
- No runner may call internal storage or bypass the public API.

## Phase 2 — GEO-24.2 and GEO-24.TS reference SDK

### Work

- Approve `docs/sdk-charter.md` covering naming, errors, cancellation, retries,
  pagination, versions and telemetry.
- Complete missing TypeScript operations and charter behaviors.
- Repair and compile all TypeScript/React/Node examples.
- Run TypeScript through the complete conformance suite and clean-consumer pack
  verification.

### Verification

- `make lint test`, SDK generation drift and release verifier pass.
- TypeScript reports 100% required conformance.
- Packed artifacts contain no workspace protocol or key-shaped value.

### Guards

- Do not rename existing stable TypeScript methods without a deprecation path.
- Do not make React hooks the only access to a capability.

## Phase 3 — Language SDK waves

Build in three reviewable batches while keeping one language per repository:

1. Python and Go.
2. Dart and Java.
3. C# and PHP.

For each language, copy the conformance runner contract and release checks from
the approved templates, generate models/stubs with pinned tools, then implement
the idiomatic facade required by the PRD.

### Verification per SDK

- Formatting, lint, unit tests and supported-runtime matrix.
- 100% required conformance and error-catalog coverage.
- Clean consumer install/build/run.
- Registry dry run, artifact inventory, checksum and secret scan.
- Compiled quick start extracted into documentation.

### Guards

- No lowest-common-denominator naming copied mechanically from TypeScript.
- No default API key, unbounded retry or telemetry body capture.
- No handwritten duplicate model when a pinned generator owns it.

## Phase 4 — GEO-24.9 coordinated release automation

### Work

- Publish an immutable contract/conformance bundle.
- Add regeneration PR automation for each SDK repository.
- Add registry-specific trusted publishing/signing and independent versioning.
- Produce the coordinated compatibility manifest.

### Verification

- A manual `publish=false` rehearsal produces installable artifacts without publishing; a V2 tag is protected release intent.
- A deliberate contract break fails before any registry step.
- Provenance, version, API target and tested dataset version are inspectable from
  every artifact.

## Phase 5 — GEO-24.10 documentation parity

### Work

- Build quick starts for TypeScript, React, Python, Go, Dart, Java, C#, PHP and
  curl from compiled examples.
- Publish capability and compatibility matrices.
- Document cancellation, retry, pagination and typed-error patterns per language.

### Verification

- Documentation CI compiles/runs every extracted example.
- Link checking and secret scanning pass.
- Fresh-environment walkthroughs complete one anonymous and one keyed request.

## Final verification

- Contract lint/drift/breaking checks.
- Seven-language conformance matrix.
- Cross-protocol semantic parity.
- All registry artifact and clean-consumer tests.
- Security/privacy scan and dependency review.
- Documentation build/link/example checks.
- Release manifest signed and reconciled with published registry metadata.
