# GhanaGeo V2.0 Distribution — Product Requirements

**Status:** Draft for approval  
**Depends on:** `docs/v2/v2.0-sdk-brd.md`

## Product contract

The canonical OpenAPI, protobuf, GraphQL and error-catalog files remain the
source of truth. TypeScript supplies the first executable interpretation of
client ergonomics and is itself required to pass the same conformance suite.

### Supported languages

| Language | Product | Required baseline |
|---|---|---|
| TypeScript | `@ghanageo/core`, `client`, `react`, `node`, `data`, `proto`; `ghanageo` umbrella | Browser and Node, ESM; React SSR/hydration |
| Python | `ghanageo` | Sync/async, typing, Pydantic, pandas/GeoPandas helpers |
| Go | `github.com/ghanageo/ghanageo-go` | `context.Context`, functional options, typed errors |
| Dart | `ghanageo` | Null safety, Future/Stream, cancellation, Flutter picker |
| Java | `dev.ghanageo:ghanageo-java` | Java 21+, records, async client, Spring Boot starter |
| C# | `GhanaGeo` | DI interface, nullable types, cancellation, async pagination |
| PHP | `ghanageo/ghanageo-php` | PSR-18/7/3, Laravel provider and facade |

## Shared functional requirements

Every general client must provide:

- Regions, districts, places, boundaries, search, autocomplete, geocode,
  reverse, nearby, dataset catalogue and download metadata.
- Anonymous-by-default requests and an explicitly supplied API key option.
- Typed errors containing `code`, transport status, `requestId` and details.
- Cancellation/deadline support appropriate to the language.
- Cursor pagination plus an idiomatic iterator/stream abstraction.
- API version and tested dataset version as separate values.
- Configurable base URL, user agent and telemetry opt-out.
- Bounded retry with jitter only for safe/idempotent reads and transient status
  classes; `Retry-After` must be honored and 4xx errors must not be retried
  except documented 408/429 handling.
- No credential, exact coordinate, request body or response body in telemetry by
  default.

## TypeScript reference requirements

Before another language copies its behavior, TypeScript must:

1. Add every missing public OpenAPI operation, including boundaries and nested
   geography paths.
2. Add cursor iterators, the shared retry policy and telemetry opt-out.
3. Preserve injectable `fetch`, `AbortSignal`, anonymous defaults and the
   existing `GhanaGeoError` shape.
4. Correct the Next.js example to use the real `regions` API and make every
   example compile in CI.
5. Resolve the repository's compiler-policy mismatch: package manifests use
   TypeScript 5.9.3 while older plan prose names 7.0.2. The package manager lock
   and verified compiler—not aspirational prose—must define support.
6. Run the language-neutral suite through a thin TypeScript runner.

## Conformance case format

Cases live under `contracts/conformance/` and are data, not executable code.
Each case includes:

- stable ID and contract version;
- protocol and operation;
- request input and fixture preconditions;
- expected status/error code and normalized result shape;
- expected quota-cost class;
- pagination/cancellation/retry assertions where relevant;
- tags for required, protocol-parity, security and language capability.

Secrets never appear in fixtures. Dynamic identifiers are captured by named
variables rather than hard-coded from a developer database.

## Non-functional requirements

- Generated code and generator versions are pinned and reproducible.
- Public APIs receive idiomatic hand-written facades over generated models.
- Package installation and a minimal request compile in a clean consumer project.
- Accessibility applies to React and Flutter UI components.
- Release artifacts carry provenance/signatures where their registry supports it.
- Supported runtime/compiler versions are tested, documented and reviewed every
  six months.

## Acceptance

A language is not “done” when it compiles. It is done when generation drift,
unit tests, live conformance, clean-consumer installation, secret scanning,
documentation examples and registry dry-run checks all pass.
