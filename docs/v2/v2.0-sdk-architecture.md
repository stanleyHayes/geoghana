# GhanaGeo V2.0 SDK Architecture

**Status:** Proposed  
**Approval gate:** No implementation before BRD/PRD/architecture approval

## Source-of-truth flow

```text
OpenAPI + protobuf + GraphQL SDL + error catalog
                    |
                    v
       generated models and protocol stubs
                    |
                    v
      idiomatic facade in each language SDK
                    |
                    v
 language-neutral conformance runner adapter
                    |
                    v
   registry artifact + compiled documentation
```

Contracts define wire behavior. `packages/client` defines the initial ergonomic
reference, but a TypeScript behavior that contradicts a contract is a TypeScript
bug, not a new standard.

## Repository topology

Recommended topology:

- This monorepo owns contracts, `contracts/conformance/`, the V1 service, all
  TypeScript packages, fixture-server orchestration and the compatibility matrix.
- Python, Go, Dart, Java, C# and PHP use dedicated public repositories matching
  their registry/module conventions.
- Contract releases publish an immutable bundle containing OpenAPI, protobuf,
  GraphQL, errors, conformance fixtures and checksums.
- Automation opens a regeneration pull request in each SDK repository. No SDK
  follows a mutable branch at build time.

This avoids making a Go module path or Maven/NuGet release depend on a nested
monorepo layout while keeping behavior centrally governed.

## Conformance architecture

- `contracts/conformance/schema.json` validates every YAML case.
- `contracts/conformance/cases/*.yaml` contains curated behavioral cases.
- `tools/conformance` starts or targets a versioned test server, loads deterministic
  fixtures and exposes case data plus result reporting.
- Each SDK implements only a small runner adapter: map an operation name to the
  public SDK call and serialize its normalized result.
- Reports use a shared JSON schema and are uploaded as CI artifacts.
- Contract CI runs TypeScript first for fast feedback, then the seven-language
  matrix. A required case skipped by any runner fails the job.

Generated cases cover operation/result shapes; curated cases cover semantics,
errors, pagination, quotas, cancellation, retries and protocol parity. Generation
must never overwrite curated cases.

## Compatibility policy

- OpenAPI changes are linted and diffed against the last public contract bundle.
- Protobuf uses Buf `FILE` breaking rules because Python and other generated
  languages are sensitive to source-layout changes.
- Error-code deletion or semantic reassignment is breaking.
- Additive contract changes trigger SDK regeneration but do not force a major
  SDK version unless the facade changes incompatibly.
- Each SDK publishes `apiVersion`, `testedDatasetVersion` and a compatibility
  matrix entry.

## Release design

Each SDK owns independent SemVer and registry credentials. A coordinated GhanaGeo
release manifest records the tested version of every language artifact. Releases
must use pinned toolchains, clean builds, artifact installation tests, credential
scans, checksums and registry provenance/signing where supported.

The existing TypeScript `sdk-release.yml` and `verify-sdk-release.sh` are the
reference for dependency-order publishing and consumer-tarball inspection. They
must be generalized, not copied with npm-specific assumptions.

## Security and privacy

- No default key in source, examples, fixtures or artifacts.
- Authorization headers and request bodies are excluded from telemetry.
- Retries never replay unsafe writes implicitly.
- Test credentials are short-lived and scoped to the conformance environment.
- Release jobs use workload identity/trusted publishing where registries support
  it and otherwise use environment-scoped secrets.

## Architecture decisions awaiting approval

| Decision | Recommendation |
|---|---|
| Behavioral reference | TypeScript, subordinate to canonical contracts |
| New SDK repository shape | One public repository per non-TypeScript language |
| Versioning | Independent SDK SemVer plus coordinated release manifest |
| Contract distribution | Immutable checksummed release bundle |
| Protobuf compatibility | Buf `FILE` rules |
| Generator policy | Pin versions; generated models plus hand-written facade |
